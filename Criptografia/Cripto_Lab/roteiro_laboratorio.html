Etapa 3 — Conversão do texto para bytes (TextEncoder)

O SHA-256 recebe bytes (números de 0 a 255), e não strings diretamente. Usamos TextEncoder para codificar o texto em UTF-8:

const encoder = new TextEncoder();
const dados = encoder.encode("Celso");
console.log(dados); // Uint8Array(5) [67, 101, 108, 115, 111]
Etapa 4 — Geração do SHA-256 (Web Crypto API) 
async function gerarResumo(dados) {
    const resultado = await crypto.subtle.digest("SHA-256", dados);
    return resultado; // Retorna um ArrayBuffer
}
Atenção: crypto.subtle.digest é assíncrono e devolve uma Promise, exigindo async/await ou .then().
Etapa 5 — Conversão para hexadecimal (64 caracteres) 
function bufferParaHex(buffer) {
    const bytes = new Uint8Array(buffer);
    return Array.from(bytes)
        .map(byte => byte.toString(16).padStart(2, "0"))
        .join("");
}

SHA-256 produz 32 bytes. Em hexadecimal, cada byte ocupa 2 caracteres, resultando em exatamente 64 caracteres hexadecimais.

Etapa 9 — Discussão de segurança
⚠️ SHA-256 NÃO É CRIPTOGRAFIA!
Criptografia é bidirecional (cifra e decifra com chave). Hash é unidirecional (apenas resume).
Não use SHA-256 puro para senhas: GPUs calculam bilhões de hashes por segundo. Senhas devem usar KDFs lentos com salt (Argon2id, bcrypt, PBKDF2).
